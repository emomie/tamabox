# Plan 08-05 — EDGE-04: SendFailed template + controller catch render switch

## Goal

Switch `MessagesController::processSend`'s `catch (RuntimeException $e)` path from "Flash error + redirect to GET `/{slug}`" to "render dedicated `send_failed` template with 500 status". Create the new template per hi-fi `SendErrors.jsx :: SendFailed` (lines 305-414). This is the only Phase 8 backend-touch (allowed under D-25). Other server-side validation failures (consent, empty body, length>2000) remain on the Flash + redirect path (D-12).

## Tasks

1. Re-read `08-UI-SPEC.md` §"Component 5 — SendFailed template (EDGE-04)" and hi-fi `SendErrors.jsx` lines 305-414.
2. Modify `src/Controller/MessagesController.php`:
   - In `processSend()` method, locate the `catch (RuntimeException $e)` block (around line 268).
   - Replace the existing 3-line Flash-and-redirect with the new render path per UI-SPEC:
     ```php
     } catch (RuntimeException $e) {
         // EDGE-04 (Phase 8 D-10) — render dedicated failure screen.

             'inbox' => $inbox,
     ```

## Risks

- The `$body` value comes from raw `$this->postString('body')` and is escaped at template render with `h()`. Confirm no double-escape paths.
- The `withStatus(500)` may interact with CakePHP's error middleware. Verify with `composer test` after change; if middleware intercepts non-2xx render attempts, fall back to `withStatus(503)` (transient) or leave default 200. CONTEXT spec leans 500; relax to "render with 200 + visible error banner" if framework fights it.
- The retry CTA points to `/{slug}` GET. The GET path re-renders the form with empty body (session-restore only fires on `?restored=1` query). User loses the body across navigation — this is documented (hi-fi shows "下書きは端末に保存されています" but that requires localStorage which is v3).
- Mocking `MessagesTable::sendMessage` in PHPUnit: `\Cake\ORM\TableRegistry::getTableLocator()->set('Messages', $mockTable)` before the action runs. If TableRegistry isolation is tricky, the test may be skipped with a `markTestIncomplete()` note — but try the mock path first.
